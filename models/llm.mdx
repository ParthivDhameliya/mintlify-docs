Neuramine provides eight open-weight language models spanning 1 B to 70 B parameters, covering everything from a lightweight assistant on a 4 GB laptop to a high-capability model on a workstation with 80 GB of RAM. Each workspace runs exactly one LLM at a time. You can switch models at any point in workspace settings — the new model is downloaded (if not cached) and inference restarts automatically.

## Inference backends

Neuramine automatically selects the best inference backend for your hardware — you do not need to configure anything manually.

<Tabs>
  <Tab title="NVIDIA GPU (vLLM)">
    When an NVIDIA GPU with CUDA 11.8 or later is detected, Neuramine uses **vLLM** for inference. vLLM is a high-throughput serving engine that delivers 30–50% faster token generation compared to CPU inference and supports continuous batching for concurrent requests.

    **Requirements:**
    - CUDA 11.8 or later
    - NVIDIA driver 520 or later
    - Sufficient VRAM for the chosen model (see hardware table below)

    Models are loaded in FP16 safetensors format from the ZIP bundle in the registry.
  </Tab>
  <Tab title="Apple Silicon (Metal)">
    On Apple M1, M2, M3, and M4 chips, Neuramine uses **llama.cpp with Metal** acceleration. All model layers are offloaded to the Neural Engine and GPU, giving near-GPU performance with Apple Silicon's unified memory architecture.

    Because system RAM and GPU memory are shared, a 16 GB M2 MacBook can comfortably run 8 B parameter models that would require a discrete 16 GB GPU card on other platforms.

    Models are loaded as GGUF files with Q4_K_M quantization.
  </Tab>
  <Tab title="CPU (llama.cpp)">
    On any other CPU, Neuramine uses **llama.cpp** in CPU-only mode. Inference is slower than GPU backends but requires no special hardware. Stick to models at or below your available RAM and expect 5–15 tokens per second on modern multi-core CPUs.

    Models are loaded as GGUF files with Q4_K_M quantization.
  </Tab>
</Tabs>

## Quantization (GGUF Q4_K_M)

GGUF is a single-file model format used by llama.cpp. Neuramine uses **Q4_K_M quantization** for all CPU and Apple Silicon deployments, which compresses model weights to approximately 4 bits per parameter. This reduces RAM usage by 60–70% versus full FP16 precision with minimal quality loss.

<Tip>
  Q4_K_M is the recommended quantization level for Neuramine — it gives the best balance of output quality and inference speed for CPU and Apple Silicon. Avoid Q2 or Q3 quantization levels unless you are severely constrained on memory, as quality degrades noticeably.
</Tip>

## Context window behaviour

The context window defines the maximum number of tokens — input prompt plus generated output — that the model can hold in memory at once. Tokens that exceed the context limit are silently truncated from the beginning of the conversation.

- Models with a **4,096-token** context (e.g. Phi-3 Mini) are suitable for short focused tasks.
- Models with an **8,192-token** context (e.g. Llama 3.2 series, Gemma 2) handle most chat and summarisation workloads.
- Models with a **32,768-token** context (e.g. Llama 3.1 8B, Mistral 7B, Qwen 2.5 14B, Llama 3.1 70B) support long documents, extended conversations, and multi-turn agent workflows.

<Info>
  Long context processing consumes proportionally more RAM. If you run a 32 K context model on hardware with only slightly more than the minimum RAM, keep your prompts short to avoid out-of-memory errors.
</Info>

## List models via the API

The `GET /v1/models` endpoint returns the full catalogue in OpenAI-compatible format. Use it to programmatically verify which models are available or to populate a model picker in your own application.

```bash
curl https://api.neuramine.ai/v1/models \
  -H 'Authorization: Bearer nrm_sk_...'
```

**Example response (truncated):**

```json
{
  "object": "list",
  "data": [
    {
      "id": "llama-3.1-8b",
      "object": "model",
      "owned_by": "neuramine",
      "name": "Llama 3.1 8B",
      "params_b": 8,
      "min_ram_gb": 16,
      "context_length": 32768
    }
  ]
}
```

<Note>
  All API requests require a valid workspace API key in the `Authorization` header. Keys follow the format `nrm_sk_{workspace_id}_{32_chars}` and are generated per workspace in **Settings → API Keys**.
</Note>
